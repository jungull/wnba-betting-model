A. THE ALGEBRA, VERIFIED NUMERICALLY (not asserted)
====================================================================================================
  Let e = y - yhat_base on the scored rows, d = the forecast shift the candidate adds,
  SST = sum (y - ybar)^2 on those same rows.  Then

      SSE_base = e.e
      SSE_new  = (e-d).(e-d) = e.e - 2 d.e + d.d
      dR2      = (SSE_base - SSE_new)/SST = (2 d.e - d.d)/SST                        [1]

  Define c* = (d.e)/(d.d), the scalar rescaling of d that maximises [1].  Then

      (d.d)/SST >= dR2   <==>   d.d >= 2 d.e - d.d   <==>   d.e <= d.d   <==>  c* <= 1   [2]
      ORACLE := max_c (2c d.e - c^2 d.d)/SST = (d.e)^2/((d.d) SST) = c*^2 (d.d)/SST      [3]

  So:  (d.d)/SST is an upper bound on the REALISED increment iff c* <= 1, and it understates
  the ACHIEVABLE increment by exactly the factor c*^2 whenever c* > 1.
  c*^2 is therefore THE exposure multiplier, and it is 1 exactly when d is the OLS fitted
  contribution on the same rows/response/base -- because then d.e = d.d identically.

  A-i  d = OLS fitted contribution, same rows/response/base:
       (d.d)/SST 0.001883808980 | ORACLE 0.001883808980 | realised 0.001883808980 | c* 1.000000000000000
       max pairwise |diff| among the three = 1.735e-18   ->  they are ONE number
       literal two-fit check: dR2 = 0.001883808980  |diff| 1.084e-18

  A-ii SHRUNK  (coef halved -- the walk-forward case)

====================================================================================================
C. THE MINIMAL SYNTHETIC COUNTEREXAMPLE (smallest concrete case)
====================================================================================================
  Smallest case in which realised dR2 exceeds (d.d)/SST.  n = 3, one base column
  (the intercept alone), one candidate.  Everything integer or exactly representable.

  y = [-1.0, 0.0, 1.0]   base = intercept only   e = y - ybar = [-1.0, 0.0, 1.0]   SST = 2.0

  d = 0.5 * (-1, 0, 1) = [-0.5, 0.0, 0.5]   (a candidate applied at half its optimal coefficient)
     d.d = 0.5000   d.e = 1.0000   SST = 2.0000
     (d.d)/SST                 = 0.250000   <- 'the ceiling'
     realised (2 d.e - d.d)/SST = 0.750000   <- EXCEEDS IT BY 3.00x
     ORACLE                     = 1.000000   c* = 2.0000  (c*^2 = 4.00 = the understatement factor)

  THE CANDIDATE IS EXACTLY ORTHOGONAL TO THE BASE HERE (x is centred, base is the
  intercept).  So ORTHOGONALITY IS NOT THE FAILING ASSUMPTION.  The failing assumption is
  SCALE: the shift was applied at c* = 2, i.e. at half the coefficient the data supports.

  The complementary case, same three rows, shift at TWICE the optimal scale:
     (d.d)/SST 4.000000 | realised +0.000000 | ORACLE 1.000000 | c* 0.5000  -> bound HOLDS, and loosely

  C-ii  DOES COLLINEARITY WITH THE BASE BREAK IT?  1,000 draws, candidate correlated
        with the base at every level from 0 to 0.99, d always the OLS fitted contribution.
        max |c* - 1| over 1,000 draws at every collinearity level = 6.772e-15
        min (varshare / realised)                                 = 0.999999999999996
        min (rawsd_form / realised)                               = 1.000028488241079
        VIF range [1.0000, 57.03]  -- rises with collinearity, always >= 1
        VERDICT: collinearity does NOT break the bound for an OLS-fitted shift. It widens it.

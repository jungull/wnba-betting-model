# Orchestration — the persistent program graph

The scheduler for the WNBA player-model program. It decides what may run, in parallel, without
two agents contending for the same bytes; it records what actually happened in an append-only
ledger; and it refuses to let a node write a frozen artifact.

**It carries no scientific authority.** A green run here means the machinery is sound, not that
any model claim is true. Scientific authority lives in `RESEARCH_CONTRACT_V1.md`,
`PROGRAM_STATE.json`, the frozen evidence packets and the arm registry — see
[`GRAPH_POLICY.md`](GRAPH_POLICY.md) §1 for the precedence order.

---

## Layout

```
orchestration/
    GRAPH_POLICY.md            binding rules for the orchestration layer
    NODE_CONTRACT.schema.json  what every node must declare
    PROGRAM_GRAPH.json         node definitions          (generated by scripts/seed_graph.py)
    GRAPH_STATE.json           current snapshot          (DERIVED — never hand-edit)
    GRAPH_EVENTS.jsonl         what happened             (APPEND-ONLY — never rewritten)
    DECISION_LEDGER.jsonl      rulings, contradictions preserved
    ARTIFACT_LEDGER.jsonl      path -> sha256 -> when observed
    FILE_OWNERSHIP.json        write-ownership map       (DERIVED)
    nodes/                     per-node governance outputs
    prompts/                   the exact prompt each node's agent received
    reports/                   CURRENT_STATUS.md and cross-node reports
    scripts/                   the engine
    tests/                     standalone test runners, no third-party deps
```

Runtime scratch — locks, sandboxes, agent process metadata — lives under
`.claude/graph_runtime/` and is git-ignored. **Nothing there is authority.** The committed graph
must be sufficient to reconstruct the whole state.

---

## The one invariant that matters

`GRAPH_STATE.json` is a **pure function** of `PROGRAM_GRAPH.json` and `GRAPH_EVENTS.jsonl`.

```bash
python experiments/player_program/orchestration/scripts/graphctl.py state --check
```

If that fails, the snapshot was hand-edited or an event was rewritten. Both are policy
violations. The fix is never to edit the state file — regenerate it, and if the events were
tampered with, that is a finding, not a chore.

There is deliberately **no command that edits or deletes an event.** A wrong event is corrected
by appending a corrective one.

## Daily loop

```bash
cd .claude/worktrees/player-model-program
S=experiments/player_program/orchestration/scripts
```

Reconcile before any write — never trust a relayed state, including a handoff document's:

```bash
python $S/reconcile_repo.py --expect-ancestor e79ae2c --since db66a720 --scope experiments/player_program/
```

Then:

```bash
python $S/validate_graph.py            # acyclic, contract-valid, no write-scope collision
python $S/graphctl.py state            # rebuild the snapshot
python $S/dispatch_ready.py            # what can safely run right now, and what is deferred and why
python $S/graphctl.py status           # render reports/CURRENT_STATUS.md
```

Freeze a node's inputs **before** launching its agent, so "the agent saw exactly these bytes" is
checkable afterwards:

```bash
python $S/hash_artifacts.py --freeze-inputs P24_INJURY_REGIME_LEDGER
```

Freeze a raw agent output **before** anything else can read it — independence of sources is only
real if the bytes are pinned the moment they land:

```bash
python $S/hash_artifacts.py --freeze-output experiments/player_program/stage2b/P24_INJURY_REGIME_LEDGER/
```

Validate and integrate, from a **verifier** context and never from the implementing agent:

```bash
python $S/validate_node.py P24_INJURY_REGIME_LEDGER --worktree ../graph-P24 --emit-event
python $S/integrate_node.py P24_INJURY_REGIME_LEDGER --branch graph/P24_INJURY_REGIME_LEDGER   # dry run
python $S/integrate_node.py P24_INJURY_REGIME_LEDGER --branch graph/P24_INJURY_REGIME_LEDGER --apply
```

## What the engine refuses to do

* dispatch two nodes whose `allowed_write_paths` or `owned_files` overlap, unless a dependency
  edge already serialises them (`dispatch_ready.py`, `validate_graph.py`)
* merge a branch that touched a frozen path, or that wrote outside its declared scope
  (`frozen_path_guard.py`, `integrate_node.py`)
* let a registry edit pass as an append — every pre-existing record must survive byte-identically
* let an `experiment` node exist without a preregistration among its ancestors
* let `P41` (downstream turnover) precede `P40` (primary possession adjudication)
* treat a `SUPERSEDED` dependency as satisfied — superseding a node does not conjure its evidence
* lose a failure: a retry appends `node_reset`, it does not erase `validation_failed`

Each of those is covered by a test in `tests/test_graph_engine.py`.

## Adding a node

Edit `scripts/seed_graph.py`, not the JSON. Write ownership is derived there from lane and id, so
a collision cannot be introduced by typo — and `validate_graph.py` checks it independently anyway.

A new node must declare a stable id, its reason, its parent finding, dependencies, path ownership,
outputs, validators, stop conditions and its **epistemic status** — what its output is, and what
it is not. A node whose evidential standing is unstated cannot be integrated; that check is in the
contract validator, not just in this README.

Then:

```bash
python $S/seed_graph.py && python $S/validate_graph.py && python $S/graphctl.py state
python experiments/player_program/orchestration/tests/test_graph_engine.py
```

## Where it stops

Two nodes carry `human_gate: true` and will never auto-merge:

* `P43_CHAMPION_DECISION` — replacing Arm D as the frozen champion
* `O16_SHARED_SCHEMA_ADOPTION` — merging a shared schema or contract change out of the isolated
  operations lane

`GRAPH_POLICY.md` §6 lists the full set of conditions that force a stop. Everything else
advances automatically.

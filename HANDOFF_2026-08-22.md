## 6. Read this section twice — the failure modes are the real inheritance

This coordinator made every one of these. They are not hypothetical.

* **A caveat that never becomes a screen is decoration.** "Measured against consensus, not
  truth" was carried for four exchanges as boilerplate. When finally tested, the sign flipped
  and the strategy died (D172). If you write a caveat, schedule the test.
* **Verify the exit code belongs to the thing you think it does.** A push was reported exit 0
  while GitHub had rejected it; the code belonged to the wrapper. Confirm pushes with
  `git ls-remote`, not `$?`.
* **A relaxed check that cannot fire is worse than the noisy one it replaced.** The O16 fix
  needed three attempts and a tamper test each time; the first two versions passed the tamper
  test and would have shipped dead (D171).
* **A preregistered control can be empty by construction.** M32's negative control could never
  have fired. Had the primary come back positive, it would have reported a passing control that
  tested nothing (D172 DEFECT 1).
* **Do not quote a number across incommensurable settings.** A 2.4× dilution figure taken from
  a different row set and base collapsed to 1.21 when recomputed on one frame (D161).
* **Never re-hash an edited frozen prereg — restore the bytes.** Nearly shipped once during a
  node rename (D158).
* **Check the graph before creating a node.** M29 collided with an existing PASSED node.
* **Hard-pinned display figures in tests go stale silently.** Three had to be converted into
  derivations during the revision-9 repoint; their suites kept passing while the artifacts they
  checked were stale (D168, D169).
* **Before recommending an asset, check its date coverage and its point-in-time legality.** The
  injury tape was recommended, then found unusable at the cutoff, then found usable for 28% of
  rows — three messages, three corrections (D173→D175).
* **An anomaly in your own output is evidence, not noise.** M03's cadence table showed a
  five-minute-era p90 of 15.0 min. That was a second cadence tier hiding in plain sight, read as
  noise, and it made three same-day reports wrong (D179). When a percentile disagrees with the
  median by 3×, that is a distribution telling you it is not unimodal.
* **A correctly observed fact can still be wrongly explained, and the explanation is what gets
  quoted.** The 406-second quote age in M24 was real; "the decision path is too slow" was not.
  The board had simply been built inside the slow tier. Check the mechanism before naming a
  cause.
* **Attribute a loss to a measured cause, not the nearest familiar one.** M08 charged all 54
  discarded episodes to the D154 uptime limit because uptime was the known problem. Measured, it
  was 48% blackouts and 41% the daytime cadence tier — and unlike uptime, that 41% *would*
  respond to a cadence change.
* **A positive assertion against a mutable constant grades its own homework.** Removing a field
  from `REQUIRED_TIMING_FIELDS` left the check "all five required fields present" **passing**,
  because it validates the schema against the same constant that was edited. Only the negative
  case caught it. Keep negative cases.
* **A rule that stakes nothing by judgement can be argued out of; one that stakes nothing by
  arithmetic cannot.** M24 is built on that distinction, and its test suite proves the claim in
  *both* directions — a policy hard-wired to return zero would pass every one-directional test.

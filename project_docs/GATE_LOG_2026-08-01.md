   `.git/`.

A third, in `verify_all.py` itself: printing a failing check's captured output crashed the runner
under a cp1252 console, hiding the real failure behind a `UnicodeEncodeError`. The echo is now
encoding-safe.

## 7. Fourth pass — provenance, and the end of hard-coded counts

### 7.1 A manifest cannot be certified "at" a commit it predates

Stored manifests recorded only `root_commit`. That was misleading in a specific way: a manifest is
captured from a **working tree**, which is normally dirty relative to HEAD and whose changes become
the *next* commit. So `OPERATIONAL_INPUTS_2026-08-01T1954Z.json` carries
`root_commit = 3096c5d` although the tree it measured became **`c742263`** — inviting the reading
"exact-commit certification at 3096c5d", which is false in both directions.

A commit also **cannot self-identify by embedding its own final hash**, so the producing tree is
now identified by *content* instead. Every manifest carries a `producer_tree` block:

| field | meaning |
|---|---|
| `head_commit_at_capture` | the commit the tree **descends from** — explicitly *not* a claim the run happened at that commit |
| `working_tree_clean_vs_head` | whether the tree was clean (it usually is not) |
| `producer_code_sha256` | digests of the operational code actually executed — `daily_certify.py`, `operational_input_manifest.py` |
| `tracked_diff_sha256` | digest of the full `git diff HEAD` |
| `untracked_files_sha256` | digest of the sorted untracked-file list |
| `producer_tree_identity_sha256` | one digest over all of the above |

Two runs agree on this identity iff the producing tree agreed. **No layer-B result in this log is
an exact-commit certification, and none is described as one.**

### 7.2 Hard-coded gate counts are gone

The third pass claimed the module docstrings now pointed at `REPOSITORY_CHECKS` "rather than
restating a number that keeps moving". Half true: both docstrings kept a hard-coded
*"currently 10 checks"*, and `tests/test_gate_layers.py` asserted `== 10`. Replacing one stale
number with another is not fixing the class of error.

All three are removed. **`len(verify_all.REPOSITORY_CHECKS)` is the only source of truth.** The
test now asserts membership properties — non-empty, distinct names, `daily_certify` absent, this
suite wired in — instead of a cardinality. §5.2 above is corrected accordingly.

## 8. Fifth pass — a provenance contradiction, and post-push verification

### 8.1 The manifest attested code that could not have written it

`OPERATIONAL_INPUTS_2026-08-01T2032Z.json` records
`operational_input_manifest.py = c1231b25…` — the **parent `c742263`** version. The file at
`30ff762` is `398b4011…`. **The attested code cannot have emitted the `producer_tree` structure it
was attesting**, because that structure did not exist at `c742263`.

Cause: `producer_tree_identity` hashed `root/<name>` — the copy under the audited checkout — while
the code actually executing lived in the worktree. Two same-named files, different bytes, and the
manifest attested the wrong one.

Fixed, and the fix is self-checking:

- the **generating file** is hashed via `__file__` and re-hashed as a self-check;
- the same-named copies under `root` are recorded **separately**, with an explicit
  `producer_code_mismatches` list. The current run correctly reports the mismatch rather than
  hiding it;
- untracked files are hashed by **name *and content***. Previously only names were hashed, so equal
  names with different bytes collided — which meant the old *"agree iff the producing tree agreed"*
  claim was not supported by its own domain. The claim is now **narrowed** to an explicit
  `identity_scope`: the declared producer dependency set plus the exact operational inputs, and
  **not** the whole tree.

### 8.2 Layer A is labelled by which tree it ran on

A pre-push layer-A run measures a **producer tree**, not a commit: the tree is dirty relative to
HEAD and its content becomes the *next* commit. A commit cannot certify itself in advance.

So each layer-A result below is labelled, and a **post-push run from the exact pushed commit** is
reported separately in §8.3.

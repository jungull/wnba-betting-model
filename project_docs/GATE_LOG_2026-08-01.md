## 5. Second pass — completing the separation (after the 2026-08-01 18:55Z review)

The first pass reported the two layers apart but left three things unfinished.

### 5.1 The hook still enforced the wrong layer

`.git/hooks/pre-push` ran the **whole** gate, so a clean checkout — which by design cannot hold
git-ignored capture files — would be refused a push for lacking them. The hook installed by
`verify_all.py --install-hook` now runs

```
verify_all.py --repository-gate
```

**layer A only**. Layer B is run separately on the capture machine, always paired with its input
manifest. `verify_all.py` no longer prints any cross-layer aggregate; it prints
`REPOSITORY GATE: <state> (n/n checks green)` and `OPERATIONAL CERTIFICATION: <PASS|WARN|FAIL>`
as two separate results, and `--quick` is retained as an alias of `--repository-gate`.
`tests/test_gate_layers.py` (34 assertions) fails if the layers are merged, if the hook stops
passing the repository-gate flag, if a cross-layer aggregate reappears, or if an operational WARN
is silently reported as PASS.

### 5.2 The manifest did not bind everything B1 consumed

The first manifest bound the odds snapshots, `capture_log.csv` and `possessions.parquet` — but
`daily_certify` also read the **untracked injury PDF** and the **dirty tracked `injury_log.csv`**,
and listing a filename under `dirty_tracked_files` is **not** a content binding.

`operational_input_manifest.py` was rewritten to walk `daily_certify` **check by check**, resolve
every declared input, classify each by git status, and hash **everything the commit cannot bind** —
`ignored`, `untracked`, **and** `dirty_tracked` alike. Inputs that are tracked and clean are
audited and counted but deliberately not hashed: the commit already binds them.

Two defects in that tool were found and fixed while validating it, both worth recording because
each produced a *confidently wrong* manifest rather than an error:

1. **`check-ignore` received corrupted paths.** With `text=True`, Python translated the piped
   newlines to `\r\n` on Windows, git treated the trailing `\r` as part of each pathname, and the
   batch ignore-check silently matched almost nothing — so **every ignored odds snapshot was
   labelled `untracked`**. Input is now sent as bytes.
2. **A `**/*.manifest.json` glob swept in nested worktrees**, hashing sibling checkouts' copies as
   if they were operational inputs. The audit now imports the real `FITTED_ARTIFACT_GLOBS` from
   `asof_invariant` (so it cannot drift from the check it audits) and excludes `.claude/` and
   `.git/`.

A third, in `verify_all.py` itself: printing a failing check's captured output crashed the runner
under a cp1252 console, hiding the real failure behind a `UnicodeEncodeError`. The echo is now
encoding-safe.
